# Carlos Mercado — Level 13 Teaching Production System v1.0

## Purpose
This system is the source of truth for converting raw course materials into a coherent teaching package for Carlos Mercado’s Level 13 / IJEP Saturday classes.

The package must be designed as one instructional system, not as separate documents. The lesson plan defines the instructional architecture; the PowerPoint implements that architecture in class; assessments measure the stated objectives; homework extends or evaluates the same learning targets.

## Core Planning Order
Source analysis → 3 SMART objectives → time/cycle map → assessments/evidence → teaching activities → transitions/feedback → homework → editable slide deck → final alignment audit

## SMART Objectives
Every Saturday lesson contains exactly 3 SMART objectives unless explicitly requested otherwise.

Each must include:
- an observable student action
- the specific target language/skill/content
- a quantity or accuracy threshold
- the activity that measures it
- the duration or size of the measured output

Use the stem: **By the end of the lesson, SWBAT:**

Examples of measurable evidence:
- 2-minute paired conversation
- 1-minute oral presentation
- 8 original sentences
- 6 target expressions
- 5 follow-up questions
- 10-line paragraph
- 80–100-word response
- 6/10 listening details

Avoid vague objectives such as understand, learn, practice, or be familiar with unless followed by observable evidence.

## Pedagogical Flow
Use:
Activate/retrieve → contextualize → explicit instruction/model → controlled practice → guided production → communicative production → measurable assessment → feedback/retrieval

### Grammar
Meaning → grammatical role → form → controlled decision → production.
Students should explain why an answer is correct.

### Vocabulary
Context → infer → confirm → controlled use → personalized use → communicative production.

### Listening
Purpose → first listen for gist → second listen for detail → measurable check → language noticing → follow-up output.
Do not reveal the transcript before assessment unless required.

### Reading
Prediction/context → purposeful reading → comprehension → language noticing → interpretation/discussion → output.

### Speaking
Provide:
- scenario/context
- communicative purpose
- target language requirement
- minimum quantity
- time limit
- prompts/clues
- model when needed
- follow-up questions
- success criteria

### Writing
Specify genre, model/reference, organization, length, target language, submission requirements, and criteria when available.

## Activity Design
Every important activity should make clear:
1. what students do
2. why
3. what target language/skill they must use
4. how much they must produce
5. how long they have
6. who they interact with
7. how success is measured

Preferred progression:
Teacher model → individual decision → pair/group comparison → communicative production → teacher feedback

## Assessment
Assessments align directly with the 3 objectives.

Use appropriate evidence:
- grammar checkpoint
- listening comprehension
- oral production
- pair conversation
- reading task
- written response
- Google Classroom evaluation
- cumulative retrieval

Instructions specify output quantity, time, required structures/items, success criterion, and interaction mode.

## Google Classroom and Homework
Homework must be detailed enough that another teacher could explain it without guessing.

Include when supported:
- exact assignment name
- due date
- source/reference page
- every required section/task
- expected length
- minimum target expressions/structures
- submission instructions
- relevant restrictions
- what to review before completing it

Do not write only “Complete GC homework.”

## YouTube / External References
Use selectively for warm-up, contextual introduction, quick grammar preview, authentic listening, or reinforcement.
Include title/source, link, approximate segment, what students should notice, and the attached task/questions.

## PowerPoint Design System
### Non-negotiable
The PowerPoint remains fully editable. Never flatten the entire deck into slide images merely to preserve appearance.

### Visual source of truth
Use the accepted editable Relative Clauses master deck / Deck 1–3 system unless explicitly told to redesign.

Preferred characteristics:
- light/off-white or very light lavender background
- dark navy typography
- restrained indigo/purple accents
- thin gray rules
- rounded white cards only where useful
- subtle shadows
- large readable headings
- small uppercase section labels
- generous whitespace
- strong visual hierarchy
- layout varies by teaching purpose

Avoid:
- dark mode
- crowded slides
- tiny text
- repeating the same card layout everywhere
- unnecessary redesign
- image-only slides
- overlaps/cut-off text

### Exercise rule
Exercise slide → separate Answer Key slide immediately after it.
Never show answers on the exercise slide unless it is a deliberate guided demonstration.

## Quality-Control Audit
Before delivery verify:

### Alignment
- exactly 3 SMART objectives
- each has a measurable quantity
- each has an assessment/output
- each has a corresponding lesson-plan activity
- the deck contains the material to perform that activity
- homework reinforces or extends the lesson

### Timing
- activities fit institutional time slots
- breaks/transitions remain intact
- major assessments have enough time
- workload is realistic

### Pedagogy
- retrieval before answers
- controlled practice before demanding production
- speaking/writing is scaffolded
- reasoning is required
- feedback is planned
- final tasks require meaningful output

### PowerPoint
- fully editable
- no accidental rasterization
- no overlaps/cutoff
- classroom-readable fonts
- separate answer keys
- links work where needed

### Excel
- correct Saturday/date/session
- correct instructor/course data
- exactly 3 objectives
- content distributed through all cycles
- interaction column populated
- detailed homework
- institutional formatting preserved

## Anti-patterns
Do not:
- flatten editable decks into images
- redesign an accepted visual system without being asked
- use repetitive card-everywhere layouts
- create objectives without numbers/time/output
- create activities that do not measure objectives
- put answers on exercise slides
- overload slides
- create speaking tasks without context/prompts/output requirements
- write vague homework
- treat Excel and PowerPoint as unrelated documents
- silently invent course content
- use YouTube as filler
